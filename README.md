# Maxwell Metzner - Computer Science Coursework

This repository is an archive of programming and computer science projects completed at Stevens Institute of Technology. It spans introductory programming, data structures, algorithms, systems programming, programming languages, and web development.

The folders are organized by course. Each assignment is independent; this repository is not one application with a single build or test command.

## Selected work

- **Systems programming in C** — Unix-style tools for file-permission searches, a small shell, multiprocessing and shared memory, and a TCP chat client. Start in [Systems Programming CS 392 (C)](<Systems Programming CS 392 (C)/>).
- **Interpreters in OCaml** — coursework exploring expression languages, parsing, procedures, references, and type checking. See [Programming Language CS 496 (Ocaml)](<Programming Language CS 496 (Ocaml)/>).
- **Interactive web projects** — HTML, CSS, and JavaScript exercises, including a browser-based animal matching game. Open [the web design course folder](<Web Design CS 146 (HTML&CSS)/>) and its [final project](<Web Design CS 146 (HTML&CSS)/Final Project/>).
- **Algorithms and graph problems** — assignments in sorting, selection, shortest paths, graph search, and related topics. See [Algorithms CS 385 (C++)](<Algorithms CS 385 (C++)/>).

## How to explore and run projects

1. Open a course folder from the map above, then choose an assignment folder.
2. Check that assignment's source, local `README` (if present), and `Makefile`/`makefile` for its setup and build instructions. Toolchains and requirements differ by assignment.
3. The matching-game final project is static web content: open `index.html` in its folder in a browser to view the home page; use its **Game** link to play.

Some projects include tests or starter files; run tests from the specific assignment directory using that project's tooling. There is no repository-wide test suite.

## Notes

- This is a learning archive, not a claim that every exercise is production-ready. Some course directories include assignment handouts, starter code, generated files, or partial work.
- Some work was completed with classmates. Collaborators are credited in the relevant source files or project pages; a few submissions are not present because they were submitted by a partner.
- The repository preserves its course-and-assignment organization so that the original context remains visible. Generated build output and operating-system metadata are excluded from future additions.
